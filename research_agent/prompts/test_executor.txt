Run this Bash command, replacing TEST_CASES_JSON with the actual JSON array from Step 1:

<result_schema>
Each entry in results.json must have exactly these fields:
- test_id: string — unique identifier for the test case
- test_type: string — "positive" or "negative"
- endpoint_path: string — the path portion of the URL (e.g. "/accounts/123")
- expected_status: integer — the HTTP status code expected
- actual_status: integer or null — the HTTP status code received (null on connection/timeout failure)
- passed: boolean — true only when actual_status equals expected_status and no error occurred
- latency_ms: float — round-trip time in milliseconds (0.0 on failure before response)
- request_body: object or null — the request payload sent, null if none
- response_body: any — parsed JSON response body, or raw text, or null on failure
- error: string or null — error message for connection/timeout failures, null on success
</result_schema>

<execution_rules>
- MAX_WORKERS = 4 — always use exactly 4 workers, matching the agentic_test default
- TIMEOUT_SECS = 10.0 — enforce httpx.Client(timeout=10.0) per request
- Use concurrent.futures.as_completed() to collect all futures before writing output
- Sort results by test_id ascending after all futures complete (deterministic ordering)
- Write results.json exactly once, atomically, after all futures resolve — no incremental writes
- Connection errors and timeout exceptions must be caught, recorded with passed=False and error field populated
- Never write partial results; wait for all futures to complete first
</execution_rules>
